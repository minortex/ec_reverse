# 01 硬件与整机事实

## 1. 组成

| 部件 | 识别 | 依据 |
|---|---|---|
| 主 EC | ITE **IT5571** | SFR 定义、`ITE EC-V14.6` 字符串（镜像 `0x50`） |
| PD 控制器 | ITE **ITE8850-PD**，固件 `V0.27` | 镜像 `0x20040` 自标识 |
| Flash | **XMC XM25QH80**，8 Mbit / 1 MiB | JEDEC `20 40 14 20` + 芯片丝印 |
| 主机接口 | H2RAM/SMFI @ `0xFED50000`；I2EC @ `0x681–0x683` | 固件窗口配置、真机读取 |

主 EC 与 PD 共用**一片** SPI Flash，但各自有独立的复位向量、中断向量与主循环（见 03）。

## 4. 复位与退出语义（D0）

| 动作 | 效果 |
|---|---|
| SPI 子事务结束：direct `0x05`（ID 路径）或 Fast Read 状态握手 | 只结束当前子事务 |
| `0x66←0xFC` + KBC `0xAE` | 退出 Follow Mode，**不**让 EC 应用固件重新运行 |
| `0x66←0xFE` | EC Reset → 平台直接复位 |
| Linux `poweroff` | 只关主机；EC 仍由电池/待机供电，需长按电源键做硬件复位 |

在 Follow Mode 停留约三分钟后平台自动强制断电（watchdog / 失联超时 / 电源保护之一，
未定位具体计时器）。所以“不发送复位”不是可长期维持的状态。

**持久化教训**：平台复位时 `fwrite`+`fflush` 不足以保留文件（Btrfs 上曾出现 0 字节）。
dump/写入必须走：同目录临时文件 → 完整写 → `fdatasync` → 原子 rename → 目录 `fsync` → `syncfs`。

## 5. 可刷性

| 命题 | 置信度 | 依据 |
|---|---|---|
| 四个连续 64 KiB block | 高 | 文件长度、切片哈希、EFI `0x10000` 分块 |
| block 0/1 主 EC、2/3 PD | 高 | 两套独立向量；`0x20040` 自标识 |
| `ifux64.efi` 不做主机端验签 | 高 | 无哈希/证书/公钥/型号白名单；PE Security Directory 为空 |
| 可刷任意修改镜像 | 中高 | 输入是裸文件；缺真机写入实验 |
| EC 启动完全无验证 | 中低 | 镜像内未见验签，但 ROM/OTP 不可见 |

风险：主 EC 与 PD 共用整片镜像，错误的 bank、向量、配置或 PD 策略可导致不开机、
不充电、USB-C 异常，极端情况只能外接编程器恢复。**建立硬件恢复手段之前不要做写入实验。**

## 6. 安全边界总结

- 主机端更新链没有可信签名校验，`F.nsh` 直接 `IFUX64.efi GXxHXxx_21.200 0 1`。
- 这不是“固件无任何保护”的证明：OTP/fuse、板级写保护、EC ROM 内的未触发状态机都
  无法由镜像静态排除。
- 因此“能刷”与“刷坏能救”是两个独立问题，后者未验证。
